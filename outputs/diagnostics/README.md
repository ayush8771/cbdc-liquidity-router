# Stage 1D failed-transaction diagnostics

Read-only diagnosis of deterministic PPO failures (unrouted > 0.01% of amount), following
`docs/FAILED_SPLITTING_INVESTIGATION_PLAN.md`. Produced by `diagnose_failed_splitting.py`.
No model, environment, reward, data or checkpoint was modified, and nothing was trained or tuned.

  `outputs/experiments/stage1d_entropy_pair_seed42_20261031_153140/` (entropy 0.0 and 0.005).
- **Validation split (cross-check):** the six checkpoints in

Each replay of a checkpoint must reproduce its saved metrics exactly before the diagnosis runs. All 8 did, with a largest difference of 0.0.

## Files (per run)

- `FINDINGS.md`: the concise report. It contains the replay check, the mechanism and flags, the over-allocated bridge,
  aggregates, test overlap, validation recurrence, and an interpretation that separates facts from hypotheses.
- `failed_transactions.csv`: one row per (checkpoint, failed transaction). It holds the per-bridge fee, liquidity,
  congestion, risk, Dirichlet concentration, deterministic/waterfall/best-sample shares, and the
  requested/executed/clipped/spare amounts, plus reward components and stochastic-sample statistics.
- `summary.json`: per-checkpoint counts and aggregates.
- `replay_check.json`: replayed versus saved metrics for each checkpoint.
- `provenance.json`: git HEAD and dirty state, package versions, device, and the SHA-256 of every checkpoint, saved
  metrics file and data split. The script's own SHA-256 and git blob hash are recorded in the authoritative run only.

## Method

- **Deterministic PPO** uses the normalized Dirichlet concentration.
- **Counterfactuals:**
  - the liquidity-aware waterfall;
  - the all-zero action;
  - 200 stochastic samples per transaction, drawn by the model's own masked-Dirichlet sampler with torch seed 20261101, reset for each transaction.

  All of them run through the same `env.step()` from the same environment state. After each transaction the script checks that the state is unchanged and that the deterministic reward reproduces exactly.

## Key measured results (authoritative run)

- 51 failed rows, all in `splitting_needed` and the GBR→PHL corridor.
- All 51 are over-allocation: at least one bridge was asked for more than its liquidity, and the excess was clipped and not redistributed. None exceeds combined liquidity, whose highest ratio is amount/combined = 0.9395.
- The clipped excess has a median of 5.13% of the amount, with a range of 0.18–23.78%.
- PPO's reward is at least the waterfall's in 16 of 51 rows. Routing nothing (reward 0.0, reported unrouted 0) scores at least the waterfall in 37 of 51.
- In 40 of 51 rows, at least one single sample both completes and beats the deterministic reward. The highest-reward sample completes in 28 of 51.

## Limitations

- **Small sample:** there are few failures (2–14 per checkpoint), from one corridor, and with three seeds.
- **Test split already examined:** test-split results are diagnostic only.
- **Placeholder reward weights:** the reward uses λ = 1.0 for every term, so the reward comparisons depend on uncalibrated settings.
- **Under-requested money isn't penalised:** the environment counts unrouted as requested minus executed. A request below the full amount therefore isn't penalised for the part never requested, and the all-zero action scores 0. PPO's actions always sum to 1, so PPO is unaffected. This is about how the reward and metrics are defined.
- **Waterfall is not the optimum:** comparisons against the waterfall are against a heuristic, not against the reward-optimal action.
- **Platform:** concentrations were computed on CUDA (RTX 3050). On other hardware, sampled results may differ slightly.
- **Hypotheses:** the hypotheses in `FINDINGS.md` (H1–H3) have not been tested.
